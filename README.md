# KOC / KOL 合作管理系統

完整的關鍵意見消費者（KOC）與關鍵意見領袖（KOL）合作管理架構，涵蓋從策略規劃、創作者評估、合約簽署、內容執行到成效評分的全流程。

---

## 📋 概覽

本倉庫提供了一套**數據導向、法規合規、流程化管理**的 KOC/KOL 合作方案，適用於：

- 品牌行銷團隊快速啟動影響者合作專案
- 團隊成員統一執行標準與評估邏輯
- 長期累積與管理創作者資源庫
- 建立可重複、可優化的合作模式

### 核心價值

✅ **完整流程化** — 8 個階段涵蓋從找人到結案的全生命週期  
✅ **數據驅動** — 提供評分模型、成效回推公式、報價評估方案  
✅ **法規合規** — 包含廣告法規注意事項與合約範本  
✅ **實務指導** — 話術範本、常見問題解答、案例參考  
✅ **版本管理** — 所有更新都有記錄，支援團隊協作優化

## 🚀 快速開始（3 分鐘）

### 1️⃣ 我要開啟一個新的 KOC/KOL 合作案
**第一步**：下載 `templates/02_執行表單集.docx`  
**第二步**：填寫「本案規格確認表」（第一張表）  
**第三步**：按照 `docs/01_流程規範.md` 的「階段 1」繼續

### 2️⃣ 我要找合適的創作者
**參考**：`docs/02_數據評估與選擇指南.md`  
**使用表單**：`templates/02_執行表單集.docx` 中的「候選名單評估表」

### 3️⃣ 我要給創作者發 Brief
**下載**：`templates/03_合作Brief範本.docx`  
**填寫**：根據本案情況調整品牌資訊、產品說明、內容需求  
**發送**：發送給創作者，確認他們已理解

### 4️⃣ 我要建立口袋名單庫（長期管理）
**參考**：`docs/03_口袋名單管理表說明.md`  
**工具**：在 Google Sheets 按照說明建立（約 30 分鐘）

## 🎯 典型使用場景

### 場景 1：新案啟動（Day 1-3）
```
1. 開案同仁下載表單集 → 填「本案規格確認表」
2. 主管審核確認  
3. 同仁根據「流程規範」階段 1-2 開始搜尋創作者
4. 使用「候選名單評估表」記錄與篩選
```

### 場景 2：洽談與簽約（Day 4-10）
```
1. 參考「流程規範」階段 3 進行初步接觸
2. 洽談確認條件後，用「合作Brief範本」編製專案說明
3. 用「合作合約範本」準備合約（主管審核）
4. 發送 Brief 與合約給創作者簽署
```

### 場景 3：內容執行與素材收集（Day 11-45）
```
1. 參考「流程規範」階段 5 管理審稿與修改流程
2. 素材收集完畢後進入「流程規範」階段 6 授權管理
```

### 場景 4：結案與評分（Day 46-60）
```
1. 完成「執行表單集」中的「合作評分表」
2. 根據評分（80+/60-79/60-）分類到對應的口袋名單
3. 更新 Google Sheets 的口袋名單庫
4. 下次新案優先從口袋名單中調用
```

### 場景 5：口袋名單維護（每月）
```
1. 檢查「授權到期日」，到期前 30 天提醒續約
2. 定期更新粉絲數與平均互動率
3. 當有新的合作機會時，先在口袋名單中搜尋
```

## 💡 核心概念速查

### KOC vs KOL
| 維度 | KOC | KOL |
|------|-----|-----|
| 粉絲數 | 1K-10K | 10K+ |
| 互動率 | 5-10% | 1-3% |
| 價值 | 真實口碑、素材量大 | 品牌背書、廣泛觸及 |
| 合作模式 | 產品置換為主 | 付費為主 |

### 合作模式對比
| 模式 | 品牌成本 | 控制度 | 風險 |
|------|----------|--------|------|
| 產品置換 | 低（僅產品成本） | 低 | 創作者可能不重視 |
| 固定費用 | 中（固定支付） | 中 | 內容成效不如預期 |
| 分潤合作 | 低（無前期成本） | 低 | 無法保證銷售成效 |
| 保底+分潤 | 中（保底費） | 中 | 平衡成本與風險 |

### 評分標準（合作結案後）
- **80 分以上**：⭐ 優先口袋名單，下次優先洽談
- **60-79 分**：一般口袋名單，可再合作
- **60 分以下**：觀察名單，下次需重新評估

```

```
1. 在 Issues 中發起討論：「建議在候選評估表新增 X 指標」

4. 提交 PR + 更新 CHANGELOG
```

### 新增案例參考
```
1. 建立新資料夾：examples/案例名稱_日期/
2. 放入本案的「規格表」「Brief」「評分表」（已去識別化）
3. 寫一份簡短 README 說明這個案子的特色
4. 提交 PR 供團隊學習

## ❓ 常見問題

**Q: 如何快速了解整個流程？** A: 從 `docs/01_流程規範.md`閱讀「整體流程總覽」部分（5 分鐘）；然後查看「階段 1-階段 8」的執行步驟（20 分鐘）。

**Q: 我是新員工，第一次要做 KOC 合作，怎麼開始？** A: 按順序閱讀：
1. 本 README 的「典型使用場景」
2. `guides/第一次合作完整版.md`
3. 跟著下載表單、一步步執行

**Q: 我想評估某個創作者的報價是否合理，怎麼做？** A: 查看 `docs/02_數據評估與選擇指南.md` 中的「業配費用計算與報價評估模型」部分，根據粉絲數、互動率、製作工時反推合理價格區間。

**Q: 如何長期管理創作者資源？** A: 建立一個 Google Sheets 的口袋名單庫，參考 `docs/03_口袋名單管理表說明.md` 逐步建立（含公式與條件格式設定）。

**Q: 某條款或流程需要修改，我怎麼建議？** A: 在 GitHub Issues 中開啟討論（可選），或直接建立 Branch + PR 提交修改，寫清楚「為什麼改」即可。

## 🛠️ 技術說明

### 文件格式
- `.md`：流程規範、指南、說明（直接在 GitHub 網頁查看）
- `.docx`：合約、表單、Brief（需下載後用 Word / Google Docs 開啟）

### 推薦工具
- **流程規範查詢**：NotebookLM（將 `.md` 上傳，可一問一答）
- **創作者管理**：Google Sheets（長期維護口袋名單庫）
- **協議簽署**：DocuSign / Beacon（台灣）或直接 PDF 簽署
- **素材管理**：Google Drive / Dropbox（與創作者共享）

### 匯出與分享
- 想給某人發「完整規範」？推薦把 `docs/01_流程規範.md` 複製到 NotebookLM
- 想只給創作者看 Brief？直接用 `templates/03_合作Brief範本.docx`
- 想團隊一起討論某個案例？分享 `examples/` 中的案例資料夾
